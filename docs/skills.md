# Installed AIOS skills

These eleven entries are distinct native discoverable skills with their own
trigger and workflow. The number follows useful workforms, not legacy file
count. Automatic selection uses descriptions; explicit selection uses the name.
A selected phase resumes the accepted outcome rather than restarting it.
Repository-local implementation methods remain local.

| Skill | When it applies |
| --- | --- |
| [aios](../plugins/aios/skills/aios/SKILL.md) | Coordinate owner-level business priorities and cross-project work using relevant context. Repository implementation follows its local lifecycle; setup and context upkeep have separate AIOS skills. |
| [aios-build-work](../plugins/aios/skills/aios-build-work/SKILL.md) | Implement a specified substantive AIOS result and return verified evidence for lead Review. Independent repository changes use their own correctly rooted worker. |
| [aios-check](../plugins/aios/skills/aios-check/SKILL.md) | Verify AIOS installation, owner format, discovery and relevant harness setup evidence. Artifact quality uses Review; context edits use maintenance. |
| [aios-create-project](../plugins/aios/skills/aios-create-project/SKILL.md) | Create a justified new bounded Project at its final root using the live Project Template and register only after proof. |
| [aios-create-system](../plugins/aios/skills/aios-create-system/SKILL.md) | Create a justified reusable System from its live neutral seed at the final root, with a concrete primary route and independent ownership. |
| [aios-maintain-context](../plugins/aios/skills/aios-maintain-context/SKILL.md) | Curate durable AIOS owner facts and routes, or reconcile their configured Git sync. Use for requested context upkeep; repository edits and initial setup have their own routes. |
| [aios-onboard](../plugins/aios/skills/aios-onboard/SKILL.md) | Set up, resume or move an AIOS owner home and its Codex or Pi bridge. Use for onboarding or method configuration, not every task in an established home. |
| [aios-review-work](../plugins/aios/skills/aios-review-work/SKILL.md) | Review substantive AIOS work against its accepted outcome and current evidence. Return PASS, REVISE or BLOCKED without editing the subject. |
| [aios-ship-work](../plugins/aios/skills/aios-ship-work/SKILL.md) | Deliver an exactly reviewed AIOS result under existing action and destination authority, then verify delivery, recovery and the measured outcome. |
| [aios-spec-work](../plugins/aios/skills/aios-spec-work/SKILL.md) | Specify substantive AIOS work from an idea, brief or change request. Preserve accepted sources and return a bounded READY, REVISE or BLOCKED contract. |
| [aios-update](../plugins/aios/skills/aios-update/SKILL.md) | Adopt or roll back a reviewed AIOS native package at a task boundary. Plan legacy OSM or AIOS adoption without overwriting owner data or colliding skills. |

## Checks live with their work

Spec owns readiness before Build. Review owns final requirement-to-evidence
completeness. Ship owns publish safety last before an external effect. Those
gates remain explicit and observable, with focused references reached from the
phase entrypoint. They do not need three competing public evaluation skills.

Review also conditionally checks sourced client principles, owner-facing voice
and actual visual renders. Missing client values remain unknown; no personal
style rule ships. Routing to a business constraint or an installed specialist
System belongs to AIOS coordination. Configured owner Git sync belongs to
context maintenance and the Ship checkpoint. Improvement triage is conditional
Review work. These merges preserve behavior while making discovery clearer.

Create Project and Create System remain separate: their ownership decisions,
seed transfer, history handling and proof differ materially. Update deals with
native package identity and rollback, while Maintain context owns client facts
and Check observes installation/harness state. A code review should not select
an installation audit merely because the AIOS package is installed.

The [legacy behavior map](../plugins/aios/skills/aios-onboard/references/legacy-parity.md)
records dispositions for every original method and the two newer workforms.
