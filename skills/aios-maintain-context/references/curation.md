# Selective durable context

Own context mapping, local gaps, source repair and deduplication. Onboard uses
this for new/changed context; retrieval does not. Before owner writes verify
AIOS_FORMAT via [data compatibility](../../aios-onboard/references/data-format.md);
unsupported/malformed stays read-only, missing needs setup. Git-backed durable
edits use [Sync](sync.md) under recorded authority.

## Minimum useful framework

Start from accepted input and useful work; assume no owner facts or connections.

| Area | Enough to route work |
| --- | --- |
| Owner/purpose | Who is served, relevant scope and wanted result |
| Work/sources | Where priorities, records and domain facts are authoritative |
| Decisions/constraints | Applicable choices, limits, quality and authority |
| Preferences | Relevant communication, voice and working methods |
| Capabilities/ownership | Needed account, connection, Skill, System or Project |

Cover relevant areas by a verified source, minimal owner-supplied local fact,
or explicit gap/not-applicable decision. Reuse answers; inspect relevant
authorized sources before the next material question. Coverage/confirmation stays
in setup evidence, not a permanent questionnaire or empty topic files.
Optional gaps do not prevent a useful bounded result.

## Sources and local gaps

Keep facts in one canonical source. Retain a short route: source owner/account
purpose, scoped link/ID, intended use and freshness boundary. Add title/parent
or migration provenance when identity needs it. CONNECTIONS owns access path,
tested capability, exact authority and dated verification; reference it.

Do not copy, sync, summarize wholesale or harvest
external documents, statuses, inventories, schemas or histories into the home.
Read needed source sections/records for each task. Source authority is per fact:
an offer document does not own installation instructions. Recency, title or
successful access alone proves neither canonical ownership nor permission.

If useful durable knowledge has no established external home, keep only missing
owner-confirmed meaning with source/date, scope and use in a few local lines.
Prefer an existing relevant file. An inaccessible source does not mean knowledge
is absent. Leave unresolved facts unknown; invent no persona or exhaustive profile.
MEMORY holds durable corrections/preferences; topic facts use routed context.
Never retain credentials or runtime model/effort inventories.

Preserve owner corrections with provenance and narrow override scope. Surface
material conflicts. When a source covers a local fact, reconcile before replacing
duplicate detail with its route; keep unique meaning. No automatic outward publish.

## Drift and cleanup

Re-read changing facts when needed. Moves, account changes, missing objects,
denied reads, changed identity or conflict invalidate affected verification.
Report access failure without assuming deletion or using stale summaries.

Within authorized scope verify the account and find the specific source through
known identity, parent or migration evidence. Repair only when accepted migration
evidence or an owner decision establishes the replacement and a safe read passes.
A title match alone is insufficient. Ambiguity retains evidence and needs one
focused question for dependent work. Rebind routes and dated access observations
together; a new account/resource gains no broader write approval. No unrelated
account scans, global audit on every task or background monitoring.

For authorized cleanup/repair, trace removed claims to sources or retained facts.
Preserve unique decisions, overrides and gaps. Remove superseded operational
copies, even if labelled historical; keep change evidence in the task.
Registries never mirror repository plans or source.

Keep AIOS.md a short orientation/index: aim for 100 lines/6 KB and AIOS.md plus
MEMORY below 12 KB; budgets never justify losing unique knowledge. Context names
scope, Use when and source; load no whole directory. Repository workers propose
corrections; one owner writer checks exact source bytes before patching. Concurrent
changes preserve both and stop that write.
A read of MEMORY alone neither invokes this procedure nor grants write authority;
durable maintenance uses recorded or standing authority.
