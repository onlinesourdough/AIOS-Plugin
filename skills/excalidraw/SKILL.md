# AIOS:excalidraw

Turn a question, rough idea, process, source diagram or repository into a useful
editable diagram. Work directly or support another skill. Content, a manuscript,
an owner home and a brand brief are optional inputs, never prerequisites.

## Choose what to explain

Identify the reader and the question the diagram should answer. Use the supplied
sources; infer a modest first draft when enough is known. Ask only when a missing
fact changes the meaning. Distinguish observed structure, proposed changes and
unknowns. A repository diagram needs inspected code/configuration, not guesses
from the repository name or a generic architecture template.

Choose the view before drawing. Use [diagram choices](references/diagram-choices.md)
for processes, responsibility, decisions, sequences, data, comparisons and visual
thinking. For software or infrastructure, read [architecture](references/architecture.md)
to select a consistent scope, abstraction level and relationship meaning.
Separate views when one canvas would mix several questions or become unreadable.

## Open and draw

Read [toolkit operation](references/toolkit.md) for the reviewed external source,
portable setup, live canvas controls and recovery. AIOS ships this method, not
the editor or an always-on MCP connection. Reuse an already verified compatible
installation. Apply existing setup authority; otherwise keep that dependency
explicit while completing useful preparation.

In Codex, open or reuse the selected canvas in the built-in browser. Use another
browser only when the user chooses it; other harnesses use their available
selected browser. Open it yourself when supported. Inspect the actual loaded
scene before replacing or changing existing work. If browser control is missing,
report the exact limitation; a running server or successful export does not prove
an opened, visible editor. Keep a file-only result labelled as such.

Create real editable shapes, text and connections through the toolkit. Preserve
stable IDs and read the latest scene before each revision so manual edits survive.
Use layout to express the relationship: ordering, grouping, branching or nesting
should carry meaning. Keep labels readable, route connections clearly and explain
non-obvious notation. Reuse the task's language and accepted visual direction.

Inspect the live canvas, fix clipping, overlaps, misleading arrows and unnecessary
detail, then fit the selected view. Visual inspection is quality control; a
screenshot is not the requested interactive result. Image exports are optional,
when useful to an explicitly selected deliverable.

## Keep the result editable

Save `.excalidraw` source in the task/project workspace, outside the installed
skill and tool runtime. Check that the saved scene retains labels and connections
and reopens without losing work. For an edited existing source, preserve recovery
before overwriting. Leave the verified live tab open when it is the requested
result; include its current local URL and the saved source path. Do not describe
an unobserved browser session as ready or upload a scene merely to obtain a link.

For a content caller, return the diagram and optional reveal cues; the caller
owns its manuscript, image requirements and release. For engineering, return the
view's scope, source revision and material assumptions alongside the diagram.
General diagram work needs neither a content workflow nor a software lifecycle.
