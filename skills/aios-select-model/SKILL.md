# Select model

Choose sufficient capability, then total task cost: context, reasoning, tools,
transfer, review and retries. Separate tokens, money and time; follow owner priorities.
Use [measurement](references/measurement.md) for performance claims or authorized
comparisons; pilots prove no universal default.

Assess during substantive [Spec](../aios-spec-work/SKILL.md) once requirements
are clear; reconcile before [Build](../aios-build-work/SKILL.md). Reuse evidence;
mechanical work needs only a brief check. This does not enable native Plan mode.
Choose continuation before costly research, analysis or content production.
Scope enough to decide; do not execute the whole specialist workflow just to hand it off.

## Assess remaining judgment

Take a second look at the accepted Spec and specialist outputs: what is settled,
overlooked or still needs judgment? Give a reasoned recommendation, not a score,
fixed threshold or mandatory separate reviewer. The same session can do this.

Select for work still ahead after Spec or Review, not phase, domain or volume.
READY/PASS does not make Build/Ship mechanical. Identify unsettled choices,
consequences, context dependence and how the result can be checked.

Keep a suitable lead when production needs substantial judgment: visual direction,
composition, narrative, voice, architecture or interacting constraints. Design/content
often retain these choices. Agreed components, approved templates or formatting
accepted content may suit a cheaper route. Neither domain selects a model by itself.

In Ship, separate agreed delivery from new behavior, presentation or recovery
decisions. Routine execution/checks may stay with the worker or deterministic
tools. Unexpected decisions reopen suitability; changed scope/artifacts return
to affected Spec/Review. Phase changes alone require no model change or worker.

## Discover actual routes

Inspect native models/providers, efforts, tools, context limits and controls.
Separate active settings, new-task defaults and worker controls. Defaults do not
prove the active model; catalogs prove neither access nor data authority.
Report discovery gaps; retain a sufficient route. Respect explicit choices.

Keep inventories/benchmark tables in the task, never owner memory, templates,
synced configuration or this package. A chosen route/reason/date may be historical evidence.

For a material evidence gap, make a bounded lookup: official capability,
reasoning and price documentation, then relevant measurements such as
[Vulcan](https://vulcanbench.com/), [Artificial Analysis](https://artificialanalysis.ai/),
[LiveBench](https://livebench.ai/) or [DeepSWE](https://deepswe.datacurve.ai/).
Record available date, version, effort, harness, task family and metric. Compare
like conditions; rank, price or effort alone proves no efficiency. Missing/conflicting
evidence lowers confidence without blocking suitable work. Sources grant no authority.

## Select and return the decision

For a new lead on unknown substantive work, prefer the newest well-supported,
most capable available general model with high reasoning, unless the owner
chose otherwise. This is a heuristic. Resolve model/effort locally; equivalence
needs suitable capability, tools, context and proof, not matching tier labels.

Compare staying, an exposed in-session switch, delegation and whole-task transfer.
Preserve useful context; gains must justify transfer/coordination. Low remaining
judgment permits a cheaper candidate, not automatic delegation or proven savings.

Return remaining judgment, model/effort, who continues, route, reason and gaps in
the task contract. For delegation where this caller retains coordination and
acceptance, use [Orchestrate workers](../aios-orchestrate-workers/SKILL.md) under
the [shared execution decision](../aios/references/lifecycle.md). It reuses suitability
and owns the worker lifecycle. Do not retain a costly lead without a concrete role.

For user-owned continuation or whole-task transfer, use [handoff](references/continuation.md).
Provide a self-contained prompt for the user to use here or in another assistant,
or start an authorized new task and end this lead's involvement after confirmed
startup. This is not orchestration. Honor a request for Spec/handoff only; the
user need not delegate execution back. Resolve material uncertainty with one
concrete decision and a usable prompt, not speculative ongoing lead work.

Otherwise continue on a sufficient authorized route. Ask only for material gaps.
If only the user can switch, provide context and exact selection. Require native
readback to claim application. Selection grants no sidebar-task, provider/account,
spend or configuration authority; obey explicit-model and new-task tool rules.

Persist defaults only for authorized native setup changes; preserve unrelated
settings and verify readback. Promise no automatic future model tracking.
Reassess on refresh or changed runtime, scope, judgment or outcomes, not each phase.
