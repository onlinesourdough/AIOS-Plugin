# AIOS plugin development

This repository owns the portable AIOS skills, native packaging, documentation
and focused optional helpers. Read only the sources needed for the change.
Owner context and customer data do not belong in this repository.

Use the installed shared Spec, Build, Review and authorized Ship methods for
substantive changes. Small mechanical edits need a scoped diff and affected
checks. Keep one accepted contract and the native plan through implementation,
verification and review. Repository-local requirements own the product truth.

The human chooses model/effort and decides when to start a worker. Continue in
the current task by default. Use model advice when requested or a concrete
capability gap requires a choice. Start workers only under a user request or
existing matching delegation grant; preserve one writer and exact authority.

Keep one canonical skill source in `skills/`. Native adapters and marketplace
metadata expose that source; `.agents/plugins/` is required Codex metadata.
There is no empty local skill shelf. Add a repository specialist only when a
concrete repeatable responsibility needs one.

Before completion, fix in-scope findings, run the relevant maintained checks in
[verification](docs/verification.md), and review final bytes. Keep independent
review when the accepted contract requires it. Preserve unrelated work, source
provenance and recovery. Never claim runtime behavior from source checks.

[Ownership](docs/ownership.md), [verification](docs/verification.md) and
[recovery](docs/recovery.md) own local responsibilities and evidence. Prepare a
reviewable patch before any external action outside existing authorization.
